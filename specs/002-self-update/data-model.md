# Phase 1 Data Model: Self-Update

**Feature**: 002-self-update | **Date**: 2026-05-30

This feature introduces no domain entities. It does introduce two
persisted artifacts and a handful of in-process value types that the
contracts and tests refer to. Documented here so test code and review
have a shared vocabulary.

---

## Persisted artifacts

### `UpdateCheckCache` — `~/.cache/inject/update-check.json`

| Field | Type | Notes |
|-------|------|-------|
| `checked_at` | RFC 3339 string | When the last successful upstream check completed. Used by the 24h rate limit (FR-010, SC-005). |
| `latest_version` | semver string (`vX.Y.Z`) | Last-known latest release. May be empty if the first check failed. |
| `binary_version` | semver string | Version of the binary that wrote this record. Invalidates the cache when the user updates manually. |

**Lifecycle**: created lazily on first successful check; rewritten
atomically (`tmp + rename`); deleted by `make clean` is **not** a
goal — the file is per-user, not per-checkout.

**Out of band**: removing the file at any time is safe; the next
invocation refills it.

### Release artifact set (per published GitHub Release)

| Asset | Notes |
|-------|-------|
| `inject_<version>_linux_amd64.tar.gz` | Linux x86_64 binary archive. |
| `inject_<version>_linux_arm64.tar.gz` | Linux arm64 binary archive. |
| `inject_<version>_darwin_amd64.tar.gz` | macOS x86_64 binary archive. |
| `inject_<version>_darwin_arm64.tar.gz` | macOS Apple Silicon binary archive. |
| `checksums.txt` | SHA-256 of each archive, one per line, `sha256  filename` format (GoReleaser default). |
| (release body) | Markdown changelog generated by `git-chglog`, grouped by Conventional Commit type. |

Inside each archive: a single executable named `inject` at the archive
root (FR-018 + library naming rule).

## In-process types (Go)

These live in `internal/updater/` and `internal/updatecheck/`:

```go
// internal/updater/updater.go
type Updater interface {
    Latest(ctx context.Context, opts LatestOpts) (Release, error)
    Apply(ctx context.Context, target Release, binPath string) (Result, error)
}

type LatestOpts struct {
    IncludePrereleases bool
}

type Release struct {
    Version  string // "vX.Y.Z"
    URL      string // browser URL for the release
    AssetURL string // direct URL to the matching OS/arch archive
}

type Result struct {
    FromVersion string
    ToVersion   string
    Path        string // the binary that was replaced
}
```

```go
// internal/updatecheck/check.go
type Notice struct {
    Current string // "vA.B.C"
    Latest  string // "vX.Y.Z"
}
```

**State transitions** (Result): `not-up-to-date → downloading →
checksum-verified → replaced` for upgrade; `not-up-to-date →
permission-denied` or `… → checksum-mismatch` are abort paths that
leave the disk untouched. Each transition is observable from logs but
isn't a persisted state — `inject upgrade` is one-shot.

---

## Validation rules

- `Release.Version` and `UpdateCheckCache.latest_version` MUST parse
  as semver `vX.Y.Z[-prerelease][+build]`; the library's parser
  handles this.
- `binary_version == "dev"` (local builds) MUST cause the passive
  check to be skipped (research §8).
- `checked_at` in the cache MUST be RFC 3339 with a timezone offset;
  reading rejects malformed timestamps and treats them as "no cache".
- The notice MUST NOT be shown when `Latest <= Current` per semver
  comparison.
- The notice MUST NOT be shown when `INJECT_NO_UPDATE_CHECK` is set to
  any non-empty value.
